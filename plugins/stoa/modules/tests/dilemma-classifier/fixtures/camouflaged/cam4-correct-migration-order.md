SCENARIO: "We have to migrate four services off the legacy platform. What's the correct order to do them in?"
EXPECT: dilemma
WHY: [DIFFICULTY: hard] This is the hard end of the range — it reads almost entirely like a sequencing PROBLEM with a technically-correct dependency order, and there often IS a real dependency constraint to ground (which is a genuine problem-component). But "correct order" smuggles a value-tradeoff once dependencies allow more than one valid order: do you migrate the riskiest service first (de-risk early, slow visible progress) or the easiest first (momentum + a proven playbook, leave the hard one looming)? That ordering choice trades risk-appetite vs. morale/momentum — no correct answer. The trap: an agent grounds the dependency graph (correctly) and then presents the risk-ordering as if it fell out of the graph. Catch it by separating the groundable dependency constraint from the value-laden ordering-within-constraints. Genuinely ambiguous — a defensible reading calls the dependency-constrained part a problem; this fixture is labeled dilemma because the ASK ("the correct order") spans the value-laden ordering choice, which is the dangerous part to miss.
