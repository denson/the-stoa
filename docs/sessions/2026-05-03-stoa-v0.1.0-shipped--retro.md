## Cross-cutting observations

**The empirical-beat trail of Arc 19.x.** Every patch (19.1 through 19.10) was driven by a real test, never by a-priori reasoning. PRINCIPAL ran cold-clone tests in both Desktop and CLI, in fresh sessions, with cold context — and each test caught a specific failure mode the agent's reasoning had missed. The discipline `u--7yg.10` / `.18` (verify-then-execute) ramified to "verify-via-actual-test" rather than just "verify-the-claim-on-paper."

**Skill-format-as-script.** Three different patches (19.1, 19.2, 19.7) caught variants of the same root issue: how a skill markdown file FORMATS its instructions directly shapes the agent's output. Bullets with `**X**` headers get reproduced as headers; "point at X and say Y" produces visual-led narration; literal `**Teach:**` labels get emitted aloud. Agents can't reliably distinguish "skill-author formatting" from "script-content"; the format must do the disambiguation visually + the rule must be stated explicitly.

**Agent control responsibility.** Arc 19.6 clarified a discipline: the agent is responsible for releasing browser/automation control proactively, not waiting for the user to ask or to fight a buggy stop button. This generalizes: the agent's *default state* between commands is the load-bearing thing, not the explicit commands.

**Audience-fit calibration.** Arc 19.10 (KG → presentation) and Arc 19.9 (pitch refinement) both involve same-content-different-framing decisions. The case study's field-notes voice works for the beadworks team; the elevator pitch works for any technical reader; the KG-vs-presentation naming is about whether the reader needs a CS background to parse the framing. None of these are about the architecture's correctness — they're about how the framing lands with specific audiences.
