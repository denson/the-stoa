summary: |
  The design is a well-reasoned, narrowly-scoped narrowing of the .md matcher, and its mechanical claims hold up: the cfg path is byte-identical to the OLD regex (verified char-for-char), the claimed line numbers are accurate, the install glob genuinely does not deploy the tests subdir, and the frontmatter md regex behaves correctly both directions in live testing (kills all z2b body-prose false-positives; still extracts and BLOCKS a frontmatter author naming a non-Denson person, including a frontmatter authors list). The threat map (M1) and the threat-anchored probe (P2) are present and correctly shaped for the five classes they name. The verdict is REVISE, on one load-bearing structural gap and one corpus gap that hides it. THE LOAD-BEARING RISK (r1): the caller dispatches extraction mode purely by the *.md glob, but is_author_encoding_file deliberately classes LICENSE.md (line 118 LICENSE.* arm) -- and routes *.claude-plugin/*.md docs -- as config-class author files that expect whole-file cfg extraction. Because *.md wins the caller case, a LICENSE.md (or markdown plugin doc) is forced into frontmatter-only md mode, so a structured Copyright or Author NON-DENSON line in its BODY -- which the OLD gate BLOCKED -- is now LOST. This is a true-positive coverage class covered before and not after, which the directive constraint forbids; it also falsifies the M1 how-defeated claim that config files are untouched. The fix-direction (not mine to write) is to dispatch md mode only for .md files that are NOT also config-class author basenames -- i.e. let is_author_encoding_file or the caller carve LICENSE.md and *.claude-plugin back to cfg. r7 is the paired corpus gap: no LICENSE.md or *.claude-plugin/*.md true-positive fixture exists, which is exactly why the corpus would go green-both-ways while the hole is open. RULINGS on the two questions DAEDALUS asked me: (Q-B) the body Author-line residual IS acceptable for this backstop gate -- there is no mechanical predicate that admits a real body "Author: Jane Roe" while rejecting the z2b discussion prose, so re-covering body lines re-opens the bug; condition is only that the README document the delegation explicitly (it plans to). (relocate-vs-source-guard) RELOCATE is correct -- moving is_author_encoding_file into _hooklib.sh moves a pure no-I/O function, whereas the source-guard injects a new early-return path into the live gate (a fail-surface); condition is that VERA assert the deny-set is byte-identical for the full corpus and the function is defined exactly once after the move. Overall posture: structurally sound design with ONE real true-positive coverage hole (r1) that must close before build, plus the corpus class (r7) that must be added to prove it closed. Fix r1 + r7 and this is RATIFY.
